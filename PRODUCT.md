# Product

## Register

product

## Users

CFlow serves non-technical staff in functions such as HR, finance, and operations who need to assemble, review, and run local Agent workflows without learning a DSL or reading implementation identifiers.

## Product Purpose

CFlow turns a plain-language objective into an inspectable Flow, lets the user refine it on a desktop workbench, and keeps checking, testing, publishing, execution, and run history explicit. Success means a colleague can understand what will happen, approve the next step, and recover execution facts without engineering help.

## Brand Personality

Quiet, precise, and trustworthy. The product should feel like an orderly office workspace: calm enough for repeated use, direct about state and risk, and confident without looking technical or theatrical.

## Anti-references

- Marketing-style SaaS dashboards with decorative cards, oversized headings, gradients, or ornamental motion.
- Operator consoles that expose protocol names, hashes, internal IDs, or raw runtime terminology as primary content.
- Mobile-first or touch-first layouts that compromise the dense desktop workbench.
- Interfaces that encode state through color alone or compete for attention with several primary actions.

## Design Principles

- Keep the user's current task and single next action obvious.
- Prefer business language while keeping technical facts available on demand.
- Make workflow state, permissions, and execution outcomes explicit and auditable.
- Preserve a stable, dense desktop workspace for repeated operational use.
- Use visual emphasis only when it carries meaning.

## Accessibility & Inclusion

Maintain WCAG AA text contrast, visible keyboard focus, semantic labels, and status text in addition to color. Respect reduced-motion preferences and keep essential workflows fully keyboard operable. The supported surface is desktop browser use at 1280px or wider; mobile and touch layouts are intentionally out of scope.
